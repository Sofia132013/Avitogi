# Avitogi Frontend

Frontend-приложение для Avitogi — персонализированных итогов года, основанных на активности пользователя.

Приложение позволяет выбрать локальный профиль, увидеть анимированный экран загрузки и просмотреть последовательность персонализированных recap-слайдов.

## Возможности

- Выбор профиля без авторизации.
- Сохранение выбранного профиля в `localStorage`.
- Защита маршрутов, требующих выбранного профиля.
- Получение профиля, итогов и метрик с backend.
- Персонализированные адаптивные recap-слайды.
- Поддержка светлой и тёмной тем.
- Адаптация под мобильные устройства и компьютеры.
- Production-сборка, раздаваемая через Nginx.
- Поддержка Docker Compose для запуска всего приложения.

Для запуска в контейнерах:

- Docker
- Docker Compose

## Локальная разработка

Запустите backend из корневой директории проекта:

```bash
docker compose up --build postgres backend
```

После этого запустите frontend:

```bash
cd frontend
bun install
bun run dev
```

Приложение будет доступно по адресу:

```text
http://localhost:5173
```

Vite перенаправляет запросы с `/api` на:

```text
http://localhost:8090
```

## Запуск всего приложения через Docker Compose

Выполните команду из корневой директории проекта:

```bash
docker compose up --build
```

Frontend будет доступен по адресу:

```text
http://localhost:3000
```

Backend будет доступен по адресу:

```text
http://localhost:8090
```

Чтобы остановить приложение, выполните:

```bash
docker compose down
```

## Сборка и запуск frontend-образа

Соберите Docker-образ из директории `frontend`:

```bash
docker build -t avitogi-frontend:local .
```

Запустите контейнер:

```bash
docker run --rm \
  --name avitogi-frontend \
  -p 3000:80 \
  avitogi-frontend:local
```

> Frontend-контейнер ожидает, что backend будет доступен в его Docker-сети по адресу `backend:8080`. Если приложению нужен доступ к API, рекомендуется запускать его через Docker Compose.

## Переменные окружения

Переменные окружения проверяются с помощью Zod в файле `src/app/env.ts`.

| Переменная                 | Значение по умолчанию      | Описание                                              |
| -------------------------- | -------------------------- | ----------------------------------------------------- |
| `VITE_API_BASE_URL`        | `/api`                     | Базовый адрес для запросов к backend                  |
| `VITE_PROFILE_STORAGE_KEY` | `avitogi:selected-profile` | Ключ для хранения выбранного профиля в `localStorage` |

Значения по умолчанию подходят как для локальной разработки, так и для запуска через Docker Compose.

Чтобы переопределить переменные локально, создайте файл `.env.local`:

```env
VITE_API_BASE_URL=/api
VITE_PROFILE_STORAGE_KEY=avitogi:selected-profile
```

> Переменные окружения Vite встраиваются в приложение во время сборки. Изменение переменных внутри уже собранного контейнера не обновит frontend-приложение.

## Структура проекта

```text
src/
├── app/            # Провайдеры, роутер, переменные окружения и Query Client
├── entities/       # Доменные модели, схемы и API-запросы профилей и итогов
├── pages/          # Страницы приложения и recap-слайды
├── routes/         # Файловые маршруты TanStack Router
└── shared/         # Общие UI-компоненты, стили и утилиты
```

Файл, автоматически сгенерированный TanStack Router:

```text
src/routeTree.gen.ts
```

не следует редактировать вручную.

## Сценарий работы приложения

1. Пользователь открывает приложение.
2. Если профиль не выбран, route guard перенаправляет пользователя на `/profiles`.
3. Идентификатор выбранного профиля сохраняется в `localStorage`.
4. Пользователь запускает просмотр итогов с главной страницы.
5. Страница загрузки ожидает завершения анимации и получения необходимых данных.
6. Пользователь последовательно просматривает персонализированные recap-слайды.
7. На последнем слайде отображается рекомендация, полученная с backend.

## API endpoints

Frontend использует следующие endpoints:

```text
GET /api/profiles
GET /api/profiles/{user_id}
GET /api/recap?user_id={user_id}
GET /api/metrics?user_id={user_id}
```

Во время локальной разработки запросы к backend перенаправляются через Vite. В production-сборке за проксирование отвечает Nginx.
