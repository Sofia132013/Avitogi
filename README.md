## О проекте

Авитоги - это сервис с персональными «Итогами года» для пользователей Авито.

Проект показывает, каким был год пользователя: что он смотрел, в каких категориях был активен, какую роль чаще выполнял и какие достижения получил.

Реальные пользовательские данные не используются. Вместо них в проекте есть тестовые профили, объявления, категории и события.

---

## Продуктовая идея

Обычно пользователь видит только отдельные действия: просмотр, избранное, контакт с продавцом, публикацию объявления. Идея проекта в том, чтобы собрать эти действия в одну короткую историю за год.

Сервис помогает пользователю:

- увидеть свою активность за год;
- понять, был он больше покупателем, продавцом или исследователем;
- увидеть главную категорию интересов;
- получить достижения за разные типы активности;
- получить карточку с рекомендацией следующего действия на основе незавершенной истории или активного интереса;
- посмотреть итог в формате простых карточек.

## Логика генерации итогов

### Учитываемые события

В demo-данных используются события за 2025 год:

- `listing_viewed` — просмотр объявления;
- `listing_revisited` — повторный просмотр объявления;
- `favorite_added` — добавление объявления в избранное;
- `search_saved` — сохранение поиска;
- `seller_contact_started` — начало контакта с продавцом;
- `draft_created` — создание черновика объявления;
- `listing_published` — публикация объявления;
- `listing_closed` — закрытие объявления;
- `deal_completed` — завершение сделки;
- `category_viewed` — просмотр категории;
- `return_after_break` — возвращение после перерыва.

### Основные метрики

- активные дни;
- активные месяцы;
- просмотренные объявления;
- просмотренные категории;
- избранные объявления;
- начатые контакты;
- опубликованные объявления;
- самый активный месяц.

Метрики считаются только по событиям выбранного пользователя. Если событие имеет `EventID`, оно учитывается один раз. Это нужно, чтобы дубли не искажали итог.

### Карточки recap

Backend собирает итог в виде списка карточек:

- intro;
- год в цифрах;
- роль пользователя;
- главная категория;
- самый активный период;
- достижения.
- рекомендация следующего действия (пока не возвращается в recap)

### Рекомендация следующего действия

Backend дополнительно рассчитывает `recommendation`. Следующее действие, которое можно предложить пользователю после просмотра итогов. Эта функция реализована на backend, но отдельная frontend-карточка для нее пока не сделана.

Рекомендация выбирается по каскаду:

1. Незавершенная история пользователя.
2. Сильный покупательский интерес.
3. Безопасная общая рекомендация.

Незавершенная история определяется по событиям пользователя. Сейчас поддерживаются четыре сценария:

- черновик объявления без публикации;
- объявление в избранном без контакта с продавцом;
- сохраненный поиск;
- повторные просмотры объявления без следующего действия.

Если найден незавершенный сценарий, он важнее остальных вариантов. Если сценария нет, но пользователь активно смотрел объявления, добавлял их в избранное или начинал контакт с продавцом, backend предлагает открыть главную категорию. Если данных для персонального действия недостаточно, возвращается безопасный fallback, создать объявление.

Типы действий:

- `CONTINUE_DRAFT` — продолжить черновик;
- `OPEN_FAVORITES` — открыть избранное;
- `OPEN_SAVED_SEARCH` — открыть сохраненный поиск;
- `OPEN_CATEGORY` — открыть категорию;
- `CREATE_LISTING` — создать объявление.

Каждая рекомендация содержит `type`, `title` и `reason`. Поля `listing_id` и `category_id` добавляются только для действий, которым нужна конкретная цель.

Дополнительно backend возвращает поле `recommendation`, а frontend показывает его как финальную карточку recap.

### Рекомендация следующего действия

Backend рассчитывает следующее действие, которое можно предложить пользователю после просмотра итогов. Frontend добавляет эту рекомендацию в recap как отдельную финальную карточку.

Рекомендация выбирается по каскаду:

1. Незавершенная история пользователя.
2. Сильный покупательский интерес.
3. Безопасная общая рекомендация.

### Достижения

В проекте реализованы 5 достижений:

- `Точный выбор` — пользователь добавил в избранное минимум 2 объявления;
- `На связи` — пользователь начал минимум 2 контакта с продавцами;
- `Витрина года` — пользователь опубликовал минимум 2 объявления;
- `Сделка закрыта` — пользователь завершил хотя бы одну сделку;
- `Широкий маршрут` — пользователь взаимодействовал с объявлениями минимум из 3 категорий.

Достижения основаны на событиях и объявлениях. Для достижения по категориям категория определяется через объявление: событие связано с `listing_id`, а объявление связано с `category_id`.

## Архитектура

Проект состоит из трех основных частей:

- frontend - React-приложение;
- backend - Go API;
- database - PostgreSQL с миграциями и seed-данными.

Backend читает профили, категории, объявления и события из базы. Затем слой recap считает метрики, роли, главную категорию, достижения и рекомендацию следующего действия. API возвращает результат в JSON.

Frontend запускается через Nginx и показывает карточки recap.

## Запуск проекта

### Требования

- Docker;
- Docker Compose.

Для локальной разработки без Docker дополнительно нужны:

- Go 1.22;
- Bun;
- PostgreSQL.

### 1. Клонировать репозиторий

```bash
git clone https://github.com/Sofia132013/Avitogi.git
cd Avitogi
```

### 2. Настроить переменные окружения

При запуске через Docker переменные для backend и PostgreSQL уже указаны в `docker-compose.yml`.

Для локального запуска backend можно использовать файл:

```bash
cp backend/.env.example backend/.env
```

```env
DATABASE_URL=postgres://avitogi:avitogi@localhost:5432/avitogi?sslmode=disable
```

### 3. Запустить приложение

```bash
docker compose up --build
```

### 4. Открыть приложение

| Сервис | URL |
|---|---|
| Web-приложение | `http://localhost:3000` |
| Health check | `http://localhost:8090/health` |

### 5. Остановить приложение

```bash
docker compose down
```

## API

### `GET /health`

Проверяет, что backend работает.

Пример ответа:

```json
{
  "status": "ok"
}
```

### `GET /profiles`

Возвращает список тестовых профилей.

### `GET /profiles/{id}`

Возвращает один профиль по числовому id.

Если профиль не найден, backend возвращает `404`.

### `GET /metrics?user_id=1`

Возвращает метрики пользователя за год.

### `GET /recap?user_id=1`

Возвращает recap пользователя: список карточек и рекомендацию следующего действия. Frontend отображает `recommendation` как отдельную финальную карточку recap.

Формат ответа:

```json
{
  "cards": [
    {
      "type": "intro",
      "title": "Ваш год на Авито",
      "description": "..."
    },
    {
      "type": "achievements",
      "title": "Ваши достижения",
      "description": "...",
      "achievements": []
    }
  ],
  "recommendation": {
    "type": "OPEN_CATEGORY",
    "title": "Продолжите поиск",
    "reason": "Вы активно смотрели объявления — загляните в свою главную категорию.",
    "category_id": 1
  }
}
```
